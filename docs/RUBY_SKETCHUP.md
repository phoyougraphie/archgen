# Conventions Ruby et SketchUp

**Cible de développement :** SketchUp Desktop 2024–2026, Windows/macOS ; Ruby 3.2 comme base de compatibilité. Consigner version complète hôte, Ruby et OS de chaque test. Ne pas s'appuyer sur une API ajoutée après la version minimale ; publier uniquement les combinaisons vérifiées.

- `Archgen` contient toutes les constantes du plugin ; noms de fichiers en snake_case, méthodes courtes, objets de valeurs gelés. Fichiers UTF-8/LF. JSON à clés chaînes, unités dans les noms. Éviter monkey patches, globals, dépendances natives, accès réseau et modification de `$LOAD_PATH`.
- `archgen.rb` enregistre `SketchupExtension` via `Sketchup.register_extension` ; logique dans `archgen/main.rb`. Utiliser `Sketchup.require` pour les chemins internes à partir de l'extension et protéger le bootstrap contre la double exécution ; pas de chargement d'interface si l'extension est désactivée.
- `Geom::Point3d` côté writer, coordonnées `m / 0.0254` (ou `.m`, jamais les deux). Conversion des translations d'instances également. Comparer `face.normal` à la normale attendue, inverser si nécessaire. Les faces brutes restent Untagged ; la racine et des conteneurs peuvent avoir des tags ARCHGEN dédiés, sans changer le tag actif.
- Une collection `Entities` par pièce ; écrire avec `Entities#build` / `EntitiesBuilder` quand la topologie est préparée et la destination vide. Ne pas muter la collection via une autre API pendant le bloc. Version minimale : n'utiliser que les contours simples. Contrôler les retours, le nombre de faces, les normales et les limites. Garder les pièces distinctes pour éviter la fusion de jonctions.
- `MaterialManager` réutilise uniquement des ressources possédées et conformes à la clé versionnée. Collision de nom avec un matériau utilisateur : créer un nom de repli et ne pas l'écraser. Les cadres utilisent une clé (type, cotes quantifiées, matériau/révision, engine_version), une définition par clé et par modèle, dans la limite des budgets.
- `BuildingService` est propriétaire de la transaction ; writer, gestionnaires de ressources et repository ne démarrent jamais d'opération. Toute API hôte est appelée sur le thread de SketchUp. Ne pas forcer un Undo global pour réparer une action échouée.
- Ruby pur : tests Minitest avec dépendances de développement déclarées à part ; CI exécute `bundle exec rake test` après création du Gemfile/Rakefile par AG-001. La suite hôte est un script explicite de développement, jamais chargé par le produit.
- Le paquet RBZ contient `archgen.rb` et `archgen/` à sa racine, sans tests ni documentation de développement. Vérifier installation, activation, désactivation, réactivation, ouverture de panneau et absence d'erreur console. Le ZIP de spécification n'est pas un RBZ.
